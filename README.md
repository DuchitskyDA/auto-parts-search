# Поиск автозапчастей (Favorit API)

React + Redux Toolkit + Bootstrap, без TypeScript. API — веб-сервис «Проценка»:
https://lk.favorit-parts.ru/static/wsprice.pdf

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # нормализация ответов и обработка ошибок
npm run build
npm run check:api  # прогон клиента против живого API
```

Ключ покупателя — `VITE_FAVORIT_KEY` в `.env` (пример в `.env.example`). Без него
используется демо-ключ из документации. `VITE_`-переменные попадают в бандл: для демо-ключа
это нормально, реальный ключ покупателя нужно прятать за серверным прокси.

## Как работает

1. Ввод артикула → через 500 мс после паузы (от 3 символов) или по Enter —
   `GET ?key&number`. Из ответа берутся уникальные пары «производитель + номер».
2. Выбор производителя → `GET ?key&number&brand&analogues=on`. Таблица: искомая деталь,
   затем аналоги в наличии, затем без остатка. Строка — предложение склада; цена берётся
   из `warehouses[].price` (верхнеуровневый `price` документация использовать запрещает).

Состояния: лоадер на каждом этапе; ошибка API (`{"error": ...}`), сбой сети и не-JSON —
сообщение с кнопкой «Повторить»; пустой ответ (сервис отдаёт одну пустую структуру) —
«ничего не найдено». Ответ на устаревший запрос отбрасывается, предыдущий поиск отменяется.

## Структура

- `src/api.js` — запрос и разбор ошибок
- `src/normalize.js` — ответ API → список производителей / строки таблицы
- `src/searchSlice.js` — состояние и thunk'и
- `src/components/` — форма, список производителей, таблица, лоадер, ошибка
